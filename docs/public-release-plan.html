Public Release Plan

Discord Bot 一般公開計画

現在の個人サーバー向けBotを壊さずに、日程調整機能を安全な一般公開版として提供するためのゴールと作業手順です。 公開版と個人版を別ブランチで維持せず、ひとつのコードをサーバー別設定で切り替えます。

Goal

今回のゴール

ひとつのBot・ひとつのコードベースで、一般サーバーには安全で汎用的な日程調整機能を提供し、 自分のサーバーでは現在の個性やポケモン商品通知を維持できる状態にする。

公開後に実現したい状態

  • 初めて導入したサーバーは安全な標準設定で動く
  • サーバー間で投票・設定・通知が混ざらない
  • 個人専用機能は自分のサーバー以外では動かない
  • Renderの再起動後も重要な状態が復旧する
  • 少数サーバーへ月額0円前後でベータ公開できる

完成イメージ

機能を別ブランチへ分けるのではなく、共通機能とサーバー別設定を組み合わせます。 作業用ブランチは使いますが、完成後はメインへ統合します。

Mention Settings

日程調整ごとの通知・メンション設定

/scheduleから発行する一時的なWebページに通知設定を追加します。 サーバー管理者が決めた初期値を表示し、日程調整の作成者が今回だけの通知先へ変更できる構成です。

利用時の流れ

  1. Discordで/scheduleを実行する
  2. 本人だけに30分間有効なWebページを案内する
  3. Webページが対象サーバーの選択可能なロールを読み込む
  4. 日程・締切・通知先をまとめて設定する
  5. 投稿時に選択内容を投票データと一緒にNeonへ保存する

Webページで個別設定する項目

  • 日程調整の初回投稿に含めるメンション
  • 締切前リマインドに含めるメンション
  • 締切・集計結果に含めるメンション
  • 開催情報の投稿に含めるメンション
  • 各項目を「メンションなし」にする選択肢

最初の公開版で対応する範囲

  • メンションなし
  • サーバー内の選択可能なロールを1つ指定
  • サーバー共通の初期設定を今回だけ上書き
  • 選択したロール名を投稿前に確認

将来追加できる項目

  • 複数ロールの指定
  • 特定ユーザーの指定
  • 通知タイミングごとのテンプレート
  • チャンネルごとの初期設定
誤爆防止： Web画面へ自由入力された@everyoneやメンション文字列をそのまま送信しません。 BotがDiscordから取得したロールIDだけを候補にし、送信時もDiscordの allowedMentionsで実際に通知可能な対象を限定します。 @everyoneと@hereはサーバー管理者が明示的に許可した場合だけ選択可能にします。

Implementation Steps

作業手順

上から順に進めます。特にアクセス制御とサーバー別設定は、一般公開前の必須作業です。

固有要素を洗い出して分類する

ポケモン通知、固定チャンネル、固定ロール、固有口調、画像などを「共通」「設定可能」「個人専用」に分類します。

必須

マルチサーバーのアクセス制御を修正する

投票の表示・投票者一覧・締切・延長・取消・削除で、投票IDだけでなく現在のサーバーIDも必ず照合します。

最優先

Neonにサーバー別設定を追加する

guild_settingsを作り、口調、タイムゾーン、通知ロール、全体メンション可否、個人機能の有効状態を保存します。

必須

安全な標準設定を定義する

未登録サーバーでは標準口調、個人機能OFF、通知ロール未設定、@everyone禁止を初期値にします。

必須

メッセージと通知設定を切り離す

コード中の固有メッセージを標準スタイルと個人スタイルに分け、各サーバーの設定から選択します。

必須

ポケモン監視を個人専用機能として隔離する

機能全体のON/OFFと許可サーバーを設定し、自分のサーバー以外では起動・通知されないようにします。

必須

管理者用の設定コマンドを追加する

設定確認、タイムゾーン、標準の通知ロール、メッセージスタイルなどをDiscord上で変更できるようにし、操作権限を管理者へ限定します。

ベータ前

Web作成画面へ通知設定を追加する

一時セッションからサーバーとチャンネルを特定し、Botが取得したロール候補を表示します。初回投稿、リマインド、集計結果、開催情報ごとに通知先を選べるようにします。

ベータ前

Web作成リンクを再起動に耐えられるようにする

現在メモリに保存している一時セッションをNeonへ移し、Render再起動後も有効期限内のリンクを使えるようにします。推測困難な一度限りのURLとして扱い、投稿成功後に無効化します。

ベータ前

メンションを安全に送信する

保存されたロールが対象サーバーに存在し、Botから利用できることを送信直前にも確認します。削除済み・権限不足の場合は通知なしで本文だけを送信します。

必須

利用上限とデータ管理を追加する

サーバーごとの受付中アンケート数、短時間の連続作成、入力サイズ、終了済みデータの保存期間を制限します。

ベータ前

一般公開向けの見た目と案内を整える

汎用的なBot名・独自アイコン・紹介文・必要権限・利用規約・プライバシーポリシー・データ削除窓口を用意します。変更前の名前と画像は個人プロフィール用として保存します。

公開前

自分のサーバーへ固有プロフィールを適用する

自分のサーバーIDだけに現在のニックネームとアイコンを設定します。起動時または設定変更時に適用し、失敗してもBot本体の起動は継続します。

公開前

2つ以上のテストサーバーで分離を確認する

個人設定と一般設定を同時に動かし、投票、権限、通知、口調、再起動復旧が相互に影響しないことを確認します。

必須

招待制で段階的に公開する

知人の1〜3サーバーから始め、5〜20サーバーへ広げます。1か月ほど使用量とエラーを観測してから一般公開を判断します。

最終段階

Profiles

一般設定と個人設定の切り分け

一般サーバーの標準設定

  • 汎用的で親しみやすいメッセージ
  • ポケモン商品通知はOFF
  • 各メッセージの通知ロールは未設定
  • @everyoneは使用しない
  • タイムゾーンはAsia/Tokyoから開始

自分のサーバーの個人設定

  • 現在のニックネームとアイコンを維持
  • 現在のキャラクター口調を維持可能
  • ポケモン商品通知をON
  • 専用チャンネルとロールを設定
  • 必要な個人向け拡張を有効化
  • 共通の日程調整機能もそのまま利用
運用方針： 実装中は codex/public-release のような作業ブランチを使っても、 一般版と個人版を恒久的な別ブランチにはしません。完成後は共通コードへ統合し、設定で切り替えます。

Definition of Done

今回の完了条件

安全性

  • 別サーバーの投票を参照・操作できない
  • 設定変更はサーバー管理者だけが行える
  • 個人機能が一般サーバーで実行されない
  • 許可していないロールや全体メンションが通知されない

運用性

  • 設定未登録でも安全な初期値で動く
  • 再起動後も投票・リマインドが復旧する
  • 異常や使用量を確認できる

一般向け品質

  • 固有作品に依存しない名前・画像・文章
  • 自分のサーバーでは現在の名前とアイコンを維持
  • 導入方法と必要権限が分かる
  • 問い合わせとデータ削除の方法がある

ベータ公開

  • 2つ以上のテストサーバーで動作確認済み
  • 招待制で5〜20サーバーへ提供可能
  • Render・Neonの無料枠を観測できる
