# Discord 日程調整 BOT 仕様案

## 目的

Discord 上でイベントや会議の日程調整アンケートを作成し、参加者がリアクションで投票できる BOT を作る。
投票期間が終了したら自動集計し、指定されたメンバーやロールに結果をメンション付きで報告する。

## 基本の利用イメージ

### 1. アンケート作成

管理者またはイベント作成者がスラッシュコマンドでアンケートを作成する。

```text
/schedule create
タイトル: 定例会の日程調整
候補日: 2026-07-01 20:00, 2026-07-03 21:00, 2026-07-05 20:00
締切: 2026-06-30 23:59
通知先: @運営
複数投票: 可
```

BOT はアンケート用メッセージを投稿し、各候補に対応するリアクションを自動付与する。

### 2. 投票

参加者は候補日のリアクションを押して投票する。
押し直しも可能にする。

複数投票を許可する場合は、参加できる日すべてに投票できる。
単一投票にした場合は、新しい候補に投票した時点で以前の投票を外す。

### 3. 投票数表示

候補日の横に現在の投票数を表示する。

```text
日程調整: 定例会の日程調整
締切: 2026-06-30 23:59

1. 2026-07-01(水) 20:00  3票
2. 2026-07-03(金) 21:00  5票
3. 2026-07-05(日) 20:00  2票
```

リアクションが追加・削除されたら、BOT がメッセージ本文を更新して票数を反映する。

### 4. 自動集計

締切時刻になったら BOT が結果を集計し、通知先にメンションして投稿する。

```text
@運営
日程調整「定例会の日程調整」の投票が締め切られました。

最多票:
2026-07-03(金) 21:00 - 5票

結果:
1位 2026-07-03(金) 21:00 - 5票
2位 2026-07-01(水) 20:00 - 3票
3位 2026-07-05(日) 20:00 - 2票
```

## 曜日の色分け

Discord の通常メッセージ本文では、文字単位の色指定はできない。
そのため、以下のいずれかの方法で実現する。

### 推奨: Embed のフィールドや記号で表現

- 平日: 白系の記号または通常表示
- 土曜日: 青い記号を付ける
- 日曜・祝日: 赤い記号を付ける

例:

```text
⚪ 2026-07-01(水) 20:00  3票
🔵 2026-07-04(土) 20:00  4票
🔴 2026-07-05(日・祝) 20:00  2票
```

Embed 自体の色は1メッセージにつき基本1色なので、候補ごとの文字色を完全に変える用途には向かない。

### 代替: 候補ごとに別 Embed

候補ごとに Embed を分ければ、土曜を青、日曜・祝日を赤に近い表現にできる。
ただし表示が縦に長くなりやすい。

## 追加すると便利そうな機能

### 候補日の入力補助

候補日をカンマ区切りで入力できるほか、モーダル入力や対話式入力にすると作成しやすい。

例:

```text
/schedule create
```

実行後に BOT が入力フォームを表示し、タイトル、候補日、締切、通知先を順番に受け取る。

### 投票者一覧の確認

作成者や管理者だけが、各候補に誰が投票したか確認できる。

```text
/schedule voters poll_id:123
```

### 匿名投票モード

リアクション投票は誰が押したか見えやすいため、匿名性が必要な場合はボタン投票方式も選べるようにする。
ボタン方式なら BOT 側のDBに投票を保存し、表示上は票数だけを出せる。

### 締切前リマインド

締切の数時間前や前日に、未投票者へリマインドする。

```text
締切まであと3時間です。
未投票の方は投票してください。
```

未投票者への個別DMは嫌がられる可能性があるので、まずはチャンネル通知が無難。

### 同票時の扱い

最多票が複数ある場合は、同率1位として報告する。

```text
最多票が同数でした。
- 2026-07-03(金) 21:00 - 5票
- 2026-07-04(土) 20:00 - 5票
```

### キャンセル・締切延長

作成者または管理者がアンケートを閉じたり、締切を延長できる。

```text
/schedule close poll_id:123
/schedule extend poll_id:123 deadline:2026-07-01 12:00
```

### タイムゾーン固定

日本向けなら JST 固定でよい。
海外メンバーがいる場合は、作成時にタイムゾーンを指定できるようにする。

### 祝日対応

日本の祝日判定が必要。
実装候補:

- `date-holidays` などのライブラリを使う
- Google Calendar の日本の祝日カレンダーを参照する
- 年ごとの祝日データをDBに保存する

BOT としてはライブラリ利用が一番扱いやすい。


## データ構造案

### Poll

```json
{
  "id": "poll_123",
  "guildId": "discord_server_id",
  "channelId": "channel_id",
  "messageId": "message_id",
  "title": "定例会の日程調整",
  "deadline": "2026-06-30T14:59:00.000Z",
  "notifyTargets": ["role_or_user_id"],
  "multipleChoice": true,
  "status": "open"
}
```

### PollOption

```json
{
  "id": "option_1",
  "pollId": "poll_123",
  "emoji": "1️⃣",
  "startsAt": "2026-07-03T12:00:00.000Z",
  "label": "2026-07-03(金) 21:00"
}
```

### Vote

```json
{
  "pollId": "poll_123",
  "optionId": "option_1",
  "userId": "discord_user_id"
}
```

## 実装方針

### 最初の実装に向いている構成

- Node.js
- TypeScript
- discord.js
- SQLite
- 次回の締切・リマインド時刻を予約する setTimeout ベースのスケジューラー
- date-fns
- date-holidays

### リアクション方式の注意点

リアクションを使う場合、再起動後にも投票を追跡するには以下が必要。

- `messageReactionAdd`
- `messageReactionRemove`
- Partial structures の有効化
- messageId と emoji の対応をDBに保存

### ボタン方式との比較

リアクション方式:

- Discord らしく直感的
- ユーザーが押し直しやすい
- 誰が投票したか見えやすい
- メッセージ更新とリアクション同期の実装に少し注意が必要

ボタン方式:

- 投票制御がしやすい
- 匿名投票にしやすい
- 現在の票数を確実に表示しやすい
- 候補数が多いとボタン上限に当たりやすい

今回の要件では、まずリアクション方式で作るのが自然。

## 最小実装の完成ライン

1. `/schedule create` でアンケートを作れる
2. BOT が候補ごとのリアクションを付ける
3. リアクション追加・削除でDBの投票を更新する
4. メッセージ本文に現在の票数を反映する
5. 締切後に自動集計して通知先へメンションする
6. 平日・土曜・日曜祝日を記号または Embed 表現で区別する
